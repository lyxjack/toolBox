# MCP 端口分配规范

## 适用场景

启动 MCP Server、游戏后端、或任何本地开发服务时，必须查阅此端口分配表。用于避免端口冲突和确保端口分配的一致性。

## 固定端口分配表

| 端口 | 服务 | 协议 | 备注 |
|------|------|------|------|
| 3000 | Game Backend Server | HTTP | 游戏后端服务 |
| 3001 | Cocos MCP Server | HTTP | Cocos Creator MCP 插件 |
| 27124 | Obsidian Local REST API | HTTPS | Obsidian 知识库 API（默认端口） |

## 规则

### 1. 端口一旦分配，不得更改

每个服务的端口是固定的。不要因为"当前端口被占用"而临时换一个端口。临时换端口会导致：
- `.mcp.json` 配置与实际端口不一致
- 其他依赖该端口的服务无法连接
- 团队成员环境不一致

### 2. 端口冲突的正确处理流程

当遇到端口冲突时：

```bash
# Step 1: 查看占用端口的进程
lsof -i :端口号

# Step 2: 判断占用者身份
#   - 如果是目标服务自身的残留进程 → kill 掉重启
#   - 如果是其他服务 → 查阅本端口分配表，确认两个服务的正确端口
#   - 如果是系统服务占用 → 修改系统服务端口，保留开发端口分配不变

# Step 3: 一次性解决所有冲突
#   不要逐个解决，列出所有相关服务的端口需求，一次性调整到位
```

### 3. 新服务的端口分配

新增服务时：
1. 先查阅本表，确认不与已有服务冲突
2. 在本文件中注册新端口
3. 更新相关 `.mcp.json` 配置文件

### 4. 配置文件必须与分配表一致

所有 `.mcp.json`、`package.json`（scripts 中的端口）、环境变量中的端口配置必须与本表一致。修改端口分配表时，必须同步更新所有引用该端口的配置文件。

## 反模式

| 错误做法 | 后果 | 对应错误 |
|----------|------|---------|
| 端口冲突时临时换端口 | 配置不一致，下次启动仍冲突 | ERR-008 |
| 只改运行时参数不改配置文件 | 重启后恢复冲突状态 | ERR-008 |
| 不查分配表直接选端口 | 与其他服务冲突 | — |
