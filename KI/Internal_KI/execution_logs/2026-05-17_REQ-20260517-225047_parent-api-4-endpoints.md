# REQ-20260517-225047 — 三消 server 端 `/api/parent/*` 跨平台对接 4 端点

## User Intent (Original)

> 实现「三消 → 大连打滚子」跨平台对接的 4 个 /api/parent/* 端点。需求依据：V2.1 brief。范围：(1) IP 白名单 + sk 双因子鉴权中间件；(2) 幂等性服务（Mongo idempotency_keys + TTL）；(3) 四端点 GET /player-stamina / POST /grant-stamina / POST /grant-gold / POST /grant-weekly-pack；(4) 单元 + 集成测试；(5) env var 配置 PARENT_API_SK / PARENT_API_ALLOWED_IPS。

触发于滚子方答复 V2.1 brief 后（Q1 业务域名已加 / Q2 鉴权改为 IP 白名单 + sk / Q3 体力刷新频率再议）。

## PM Clarified Intent

在 `puzzle.pkgame.com` 开放一组 **server-to-server** API 给大连打滚子小程序后端：
- **查体力**（用于滚子端 prefab 上直接显示三消体力数字，玩家不必进三消）
- **回写奖励**（看广告 / 分享 / 购买后给三消账号 +体力 / +金币 / +周礼包）

**关键边界**：
- 客户端 / 滚子端代码 **不动**，纯 server 改动
- 鉴权用 **IP 白名单 + sk 双因子**（替代早期 V2 假设的 HMAC）
- 滚子方 sk / IP 列表暂未交付 —— env var 占位实现，部署时再注入
- 体力计算 / 金币 / 周礼包**全部复用现有 schema 字段**，不动 schemaVersion

## Hidden Assumptions Surfaced

12 条假设全部落地 `requirement_package.md`（A1–A12），列举几条关键：

- **A4** —— `req.ip` 正确反映来源 IP 依赖 `app.set('trust proxy', true)`。验证策略：CTO 阶段强制加配置 + 集成测试用 `X-Forwarded-For` 覆盖。挂载 P9 + [[SEC-001__trust-proxy-and-ipv4-whitelist-combo|SEC-001]]
- **A5** —— 体力软上限突破态 `heartSoftCapBreached=1` 期间，**自然回复暂停**，service 永不主动清 flag（由客户端在消耗到 ≤ cap 时清）。验证：unit `'already breached → flag stays even if new heart ≤ cap'`
- **A7** —— grant-gold **不走 reward ledger**，直接调 platformAdapter + parent_api_idempotency 记录。CTO 阶段拍板，理由：reward ledger 服务于游戏内 reward 计算，parent 通道是 thin server-to-server，混用增加复杂度
- **A10** —— userId 不存在时：查询 404 USER_NOT_FOUND；grant 类**自动创建 minimal gameSaves doc** 再应用 grant（避免奖励丢失）
- **A12** —— sk 比较强制使用 `crypto.timingSafeEqual`，并 try/catch RangeError 兜底长度差异

## Lessons Extracted

1. **IP+sk 双因子是 HMAC 的合理替代**（合作方运维成本低，安全性等价）—— 沉淀为 [[PAT-007__ip-sk-dual-factor-server-to-server-auth|PAT-007]]
2. **Mongo 11000 duplicate-key 是天然的幂等保护原语**（不必引 Redis）—— 沉淀为 [[PAT-008__mongo-duplicate-key-driven-idempotency|PAT-008]]
3. **trust proxy + IP 白名单必须配套**，且要在所有 middleware 之前 —— 沉淀为 [[SEC-001__trust-proxy-and-ipv4-whitelist-combo|SEC-001]]
4. **RouteDependencies optional 字段 + 条件挂载**：legacy e2e harness 不传新 deps 时不 crash —— 节省了改 3 个 e2e 脚本的工作量；这种"渐进式增加 DI 项"的可选化是后续多个 server feature 落地的安全模式
5. **不能 import 客户端 assets 常量** —— server 端 `STAMINA_CAP_NORMAL` 内联重复定义并加注释引用源，对比客户端 `assets/script/const/staminaConfig.ts`。这是 monorepo 跨层共享常量的最简但**显式**的方案，避免引入 shared package
6. **globalSetup.ts 是 env 校验扩展的中央枢纽**：所有 vitest 测试加新 required env 时改这一处，不必逐文件改
