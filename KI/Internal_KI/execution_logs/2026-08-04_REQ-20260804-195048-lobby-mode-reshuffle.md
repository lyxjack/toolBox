# 掼蛋大厅三模式入口重排 —— 「连打过A」上屏，经典/快速改名换位

## 需求边界

两套已上线玩法**对外改叫法 + 换落位**，玩法规则一行不改：

| 玩法（服务端不变） | 旧对外名 | 新对外名 | 新落位 |
|---|---|---|---|
| 金币三档 68000001~03（打到过A · 整场制） | 经典模式 | **连打过A** | 上排右 |
| 快速三档 68000011~13（单局 · 盲选加倍） | 快速模式 | **经典模式** | 上排左 |
| 比赛大厅 | 比赛模式 | 比赛模式 | 下排右（降位） |

命名债的来源：单局玩法上线时（[[2026-08-04_REQ-20260803-140616-quick-mode|前一个 REQ]]）「经典」已被占用，只好起了个避让性的占位名"快速模式"，入口也塞在下排小钮。产品定位一变，名字与位置必须一起动。
**教训**：入口位置是产品定位的表达，给新玩法安排"临时"入口时就要预判它转正后要占哪个坑。

## 关键决策

### D-1 用「坑位内容互换」替代用户描述的「节点搬家」

用户按搬家描述，实测发现三坑规格不同（大卡 326×207 / 301×207，小钮 208×175，底板两套）。改为只换坑内容 + 换点击去向，观感等同而改动面小一个量级。
模式已提纯为 [[PAT-044__slot-content-swap-instead-of-node-relocation|PAT-044]]，含"动手前必量的三件"。

### D-2 三条实测事实，各消掉一块工作量

| 实测 | 省下了什么 |
|---|---|
| 坑① 的 spine 图集 `dx.png` **本就印着「经典模式」四字** | 改名后那张卡**画面零改动**，不必为新"经典模式"另切图 |
| 坑② Sprite `sizeMode=CUSTOM` | 新图 329×225 被约束到 301×207，形变 0.56% → 计划里"新图更宽会与左卡重叠 11px"的 M 级风险**当场归零**，坐标一个没动 |
| 坑① handler 挂在 `DLMJLobbyGameItem` 而非层脚本 | 接线必须整体重指到宿主层脚本，否则形成跨节点隐式耦合 |

> 第二条是本轮最值钱的一笔：**先量再改**。一个被列进风险表的 M 级项，靠读一个字段就证否了，省下整轮坐标微调与回归。

### D-3 宁可加 4 行代码，不做跨节点接线

零代码方案存在（把坑② 的 clickEvent 指到坑① 卡上的组件），放弃它是因为那个方法语义是"大厅游戏条目"且内含 `gameID_` 分流；跨节点耦合无编译期保护。
最终代码改动共 **6 行**（新方法 4 行 + 两处文案常量），零逻辑改动 —— 用户原以为"不涉及代码写入"，此偏差在需求包 R1 明示后才动手。

### D-4 旧内容 `active=false` 而非删节点

比赛模式的 spine 子树保留但停用：可逆（日后要回大卡位翻一个 bool），且避开 ERR-021。代价是 prefab 里留着一棵不渲染的子树，已在 change manifest 显式记账，不算暗账。

## 执行与验收

- **模式**：serial（同一 prefab 重叠率 62.5% + cocos-mcp 单实例通道 + 数据依赖）
- **落盘**：27 条正控 + **3 条负控**（故意错值必须报红，防空钉）全绿
- **视觉**：编辑器实机截图肉眼比对，版面/图文/无遮挡全对
- **隔离**：7 改 2 增，服务端与平台侧零改动
- **判定**：**QA_HOLD** —— 静态全链路已通，但**零次真实运行**，标题实渲与点击去向待用户 preview 亲验。不假报 PASS

### Codex 交叉验证（job `task-msfivelv-nz9t9d`）

派发时**主动自曝两处盲区**并嘱其"不要采信我的话"。结论 A–F 全 CONFIRMED，G 一处漏改。它提供的、我拿不到的证据：

| 关闭的盲区 | 证据 |
|---|---|
| 运行期会不会覆盖三坑位 | 全仓无代码按名取这些节点；宿主的两个 `@property` 都指向 `listview/view/layout`，不是 rightBtn；`gameDefines=[]` 证明 `setup()` 从不被调用 |
| 子树停用有无副作用 | 仓内**根本不存在**激活 `pic_match`/`pic_Notstarted` 的逻辑 |
| 新方法无参真能进金币三档 | 逐层追通 `UIManager.push` → `UIBase.onPush` → `quick_=false` → prefab `groupList=[]`/check/jump=-1 → **必落 [68000003,02,01]** |
| 资产真实性 | library PNG 与源 PNG **SHA-256 相同** |
| 分辨率适配（我没查） | Widget 右锚 `right=136.5` 未动 → 换分辨率只平移不拉伸 |

**G 揪出的漏改**：`applyTitle()` 的文档注释里还写着旧标题「掼蛋 · 金币场」——我改了同文件两处常量说明，独漏这条注释。已当轮修复。
**这一漏的本质**：断言只扫了 `_string`/toast/Label 三个"用户可见文案面"并报"旧名清零"，**注释面不在断言里**。又是 [[ERR-084__placeholder-decorations-survive-real-asset-swap|ERR-084]]「验收清单里没有的项检出率恒为零」的复现，只是这次的盲区是文档态。
→ 文案改名批次的断言面应含三层：用户可见文案 / 代码注释与文档 / 常量名（后者通常应保留，但要带新旧对照）。
