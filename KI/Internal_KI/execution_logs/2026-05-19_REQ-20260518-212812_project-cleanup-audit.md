## Lessons Extracted

### 1. Cocos 资产/组件引用扫描必须三闸

最大教训。**单 UUID 反查会假阳性**，因为 Cocos 有 3 个并行引用渠道：
- prefab/scene 内 `__type__` 用 **compressed UUID 前缀**（前 5 hex + 18 base64）
- ts 内 `bundle.load(path)` / `resources.load(path)` / 项目自定义 `ResLoadHelper.loadCommonAssetSync(path)` 用**字符串 path**
- `.anim` 文件用 **full UUID**（不是 prefix）keyframe + `.plist` 粒子用 **textureFileName**（不是 UUID）

本 REQ 演化 3 轮才识别完：v1 漏 10 张活资源 → v2 用户挑战 "怎么还有误删的呢" → v3 加 `.anim/.plist/.json` 进 corpus，最终救回 17 张。沉淀为 [[ERR-028__compressed-uuid-deadcode-misjudge|ERR-028]]。

### 2. Archive-First 比 git rm 更适合"可回填"清理

凡是"未来可能要回填"的批量删除，本质不是删而是**搬**。Archive-First + sha256 manifest 模式在本 REQ 复用 4 次 0 错。沉淀为 [[PAT-009__archive-first-outmigration-with-sha256-manifest|PAT-009]]。

### 3. Cocos build-time test 剥离: outmigrate 比 build flag 更稳

CTO 原计划 T3.1 写 `__BUILD_TESTS__` flag + tree-shake，但 ES module 不允许 `if` 块内 static import + Cocos 动态 import 行为不确定。**fallback 方案**：直接外迁 test 文件出 `assets/`（Cocos 不会发现），mainCmpt 删 import 行 + 加注释指向 archive README。确定性 100%，恢复一键 rsync。

### 4. Compressed UUID 算法 ≠ full UUID

Cocos 压缩 UUID = full UUID 前 5 hex 字符 + 18 base64（来自 UUID 剩余字节）。所以 `"__type__": "98c94SPemNDPI6fxQMIl+TX"` 对应 UUID `98c9448f-7a63-...`。grep 类名/import 都看不见 — 这是 PM 误判 rank 的根因。

### 5. zsh for-loop 字符串切分坑

zsh 的 `for src in $(ls ...)` 会把整个输出当成单字符串（含换行 + 空格），导致 cp/rm 报 "File name too long"。正解：`while IFS= read -r -d '' src; do ... done < <(find ... -print0)`。本 REQ T1.2 第一次踩，已写入 [[PAT-009__archive-first-outmigration-with-sha256-manifest|PAT-009]] 第 3 步。

### 6. /pm 流程 + 人工 commit gate = 高密度返工保护

10 commit 全程零回归归功于：每 Phase 都让用户 Cocos Preview 验证 + 显式说 "go" 才 commit。`feedback_no_auto_commit` 项目记忆要求的"不主动 commit"在大批量改动场景下是**护城河**而非阻塞。

### 7. 文件名 grep 不够，basename 字符串假命中要警惕

Path-based 二次复扫时，仅查 basename 容易假命中常见词（`event`/`home`/`video` 在代码中频繁出现非路径用法）。解法：用 cocos path 形式 `ui/Sprite/<group>/<name>` 严格匹配，而非裸 basename。
