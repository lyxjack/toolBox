# 掼蛋「快速模式」（单局金币场）实装 —— 从改名到上服

## 需求边界

「经典玩法」占位改名**快速模式**，并把它做成可玩的单局金币场：

```
大厅点快速模式 → 初/中/高三档 → 匹配 → 盲选加倍(5s, 不加倍/加倍/超级加倍)
→ 亮级牌(翻牌合一) → 发牌开打 → 打完一副直接终局结算
```

用户明示：**先跑通流程，金币件后置**（茶位费/加倍入账/余额闸门/结算金币行全部不做，加倍只收集展示不参与算钱）。

## 关键决策

| 决策 | 结论 | 依据 |
|---|---|---|
| 首出规则 | **方案C 翻牌合一**：翻一张牌，牌点=级牌，持牌者首出 | 竞品调研：传统竞赛规则四源一致（切牌翻明牌、抓到者领出）；线上竞品 5 家随机、1 家明牌定先；"持特定牌先出"零证据。方案C 一次翻牌解决两件事，为我方原创空位。实现见 [[PAT-043__probe-core-reseed-for-host-side-variant\|PAT-043]] |
| 加倍时序 | 发牌前**盲选**（推翻原提案"看牌后 5s"） | 用户钦定。代价：失去"时点换倍率"杠杆，故档位跨度拉大到 1/2/4 |
| 判据槽位 | 新开 `iSets[0] bit4`，**禁用 `iSets[5]`/`bSets[10]`** | ⛔ 地雷：现网经典金币场按滚子模板已把那两槽误置为 1（掼蛋侧从不读故无害），复用即把现行三档经典场整体误判成快速场 |
| 级牌面板 | 快速房**隐藏**"我方/对方打几"两行，不删节点 | 两种玩法共用同一个 `WMGDGameLayer_l`，删节点会一并抹掉连打过A（钦定不动的测试版）的双方级牌显示 |
| 单局收场 | 复用现成"固定把数"机制（`bSets[2]=1`）+ 快速房强制 1 | 进贡逻辑只在第二副起触发，单局天然不触达 ⇒ 零改动 |

## 三路交叉审计与返修

独立对抗审计 / Codex / 终审复核，共 6 类缺陷全修，每项配回归钉：

| # | 缺陷 | 后果 |
|---|---|---|
| F1 | 翻到 A（1/13）时两队同为 A，级差 tie-break 判平局 | 面板"整场平局"、战绩 Draw，**而金币照按本副胜方发**（约每 53 局一次）。复核又揪出**三处漏网**（战绩/回放/episodeWinner 各算各的）⇒ [[ERR-106__same-fact-derived-in-multiple-places-forks\|ERR-106]] |
| F2/N1 | 前奏期 `GS_Sync` 泄露手牌与首出座位；`turn.timeout=0` 是"不限时"信号，诱客户端开出牌条，玩家出的牌被 yield block **静默吞掉** | 剧透 + 吞操作。闸最初还抬晚了一个状态 ⇒ [[ERR-105__fixture-collapses-phases-so-the-gap-cannot-exist\|ERR-105]] |
| F3 | 服务端墙钟从广播前起算、客户端从收到起算 ⇒ 窗末点击被丢 | 面板标"已选 ×4"桌上却不挂标。修法：服务端留 400ms 在途宽限，**下发值仍是 5 秒**（不拿玩家决策时间补网络账） |
| F4 | 建核降级路 `firstChairNo` 仍是 -1 | 客户端拿到非法 view。改由事件日志现折，主路降级路同源 |
| F5 | 加倍标挂上 2.5 秒就被自己的发牌复位清掉 | 玩家整局看不见谁加了倍。根因与 F1 同构：**把"唯一会走到这条路径的场景"想窄了**（快速模式的发牌就在加倍之后的同一副内） |
| — | 冒烟里一条断言写着"单局赢方必升级，不可能平" | 把假设当断言，单一 seed 恰好不踩边界 ⇒ [[ERR-104__assumption-written-as-assertion-and-hollow-pin\|ERR-104]] |
