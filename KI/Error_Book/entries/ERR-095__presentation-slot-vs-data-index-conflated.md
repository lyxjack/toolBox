# 一个实体两套序：拿「数据下标」去做版式决策

## 错误现象

同一 session 内两处同族翻车，症状都是「不报错、不变灰，只在特定视角或特定席位下肉眼可见」。

### 实例一 —— 结算四卡身份错位

结算页四张卡的身份角标（本家／队友／上家／下家）是 prefab 里**静态预置**的，走的是**亲疏可读序** `[0 本家, 1 队友, 2 上家, 3 下家]`；
而基类 `chairToView()` 给的是**绕桌方位序** `[0 本家, 1 下家, 2 对家(即队友), 3 上家]`。

旧码直接 `settleCards_[this.toView(chair)]` —— 把 view 当卡位下标用，**中间两卡身份对调**。

现形方式不是测试，是**用户在一局「双上」的结算截图上肉眼发现**：头游明明是队友，却被标成「上家」；更刺眼的是本家是金卡、那张写着「队友」的卡却是蓝的——队友怎么可能和本家不同色。

### 实例二 —— 复盘查看器手牌折行

同一个查看器里并存两套序：`seat` 是**绝对座号**（档案数据的下标，不随视角变的不变量）；`seatSlot(seat)` 是**版位槽**（0=S 1=E 2=N 3=W，随视角锚点旋转）。

旧码一行：

```js
var isSide = seat === 1 || seat === 3;   // 折不折成两行
```

把「折行」这个纯版式决策**钉死在了座号上**。后果：换视角后，转到 N/S（上下，有整行宽度）的两席**还在折两行**，而真正挤在左右窄边的两席**摊成一长条溢出桌面**。

最阴的是——**CSS 那半边一直是对的**（`.seat-w` / `.seat-e` 走的是 `seatCompass` 给出的槽位类），只有这一行 JS 留在绝对座号口径。**同一个渲染函数内两套口径并存**，这是本类缺陷最难察觉的形态。

## 根因分析

> **当一个实体同时存在「数据下标」与「呈现槽位」两套序时，任何版式／几何／方位决策必须走呈现槽，任何取数必须走数据下标。**

两处都是同一个动作：**在该走呈现槽的地方顺手用了数据下标**。之所以顺手，是因为在那一行的上下文里，手边已经有的变量就是数据下标（`chair` / `seat`），换算一步要多写一行——而少写的这一行不会有任何反馈告诉你少了。

## 为什么难抓

1. **不抛错**。两套序长度都是 4、值域都是 0..3，索引永远合法；越界、undefined、变灰这些常规抓手一个都不触发。
2. **常态下可能恰好对**。实例二里，若视角锚点恰为 0（恒等映射），座号与槽号完全重合，一切正常——**只有换视角才现形**。实例一里，若自己恰好坐 chair 0，view 序与卡位序也重合。开发自测的默认样本，恰恰是最容易命中恒等映射的那一个。
3. **「一半对一半错」**。CSS／静态资源／prefab 那一半往往是对的，错的只是 JS 里某一行——于是屏上表现得像随机毛病，而不像口径错误，排查方向天然被带偏。
4. **断言容易漏**。实例一修完后写了 46→52 条断言，**仍然没抓住实例二**——因为断言钉的是「取哪个 DOM 元素」「罗盘字母对不对」，没有一条钉「折行判据」。断言覆盖了元素与坐标，唯独没覆盖**版式决策本身**。

## 解决方案

两处都改成「显式换算一次，再用换算结果」，绝不让数据下标直接落到版式表达式里。

| 实例 | 旧码 | 新码 |
|---|---|---|
| 结算卡位 | `settleCards_[this.toView(chair)]` | 加显式换算表 `SETTLE_SLOT_BY_VIEW = [0, 3, 1, 2]`，按表取卡 |
| 手牌折行 | `var isSide = seat === 1 \|\| seat === 3;` | `var handSlot = seatSlot(seat); var isSide = handSlot === 1 \|\| handSlot === 3;` |

换算表写成具名常量而不是内联算式，是刻意的：它把「这里存在两套序」这件事**显式写在了代码里**，后人改动时躲不开。

## 收口证据

最终守门断言在 `gunZi_Resource/kds-game-gd/test/replayViewer.assert.mjs`（274 条）与 `gunZi_Resource/kds-game-gd/test/settleCards.assert.mjs`（52 条）。

**负控实证**（做法见 [[PAT-035__negative-control-before-trusting-a-new-assertion|PAT-035]]）：

- 把折行判据退回 `seat === 1 || seat === 3` → **报红 44 条**
- 把结算取卡退回 `settleCards_[v]`（常量 `[0,3,1,2]` 原样保留不动，确保红是判据红不是常量红）→ **报红 3 条**

两组负控都真报红，断言才算数。

## 预防规则

见 frontmatter。一句话：**取数走数据下标，摆位走呈现槽；两套序先命名分家，再把版式决策本身写进断言。**
