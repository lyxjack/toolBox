# 档案按内部 ID 归档，用户手里拿的却是另一个号

## 错误现象

回放存档以 `this.roomID`（平台内部房号，90001 系）作归档键与文件名；客户端屏幕右上角显示的「房间号」却是 `boxCode`（100001 系）。测试人员照屏幕输号 → 复盘工具永远「该房间暂无存档」。此前多轮 E2E 全绿，因为查询号都取自服务端日志而非屏幕。

## 根因分析

平台一房两号（roomID=内部索引，boxCode=展示/进房码），录制挂点顺手用了代码里最近的 `this.roomID`，没有从「谁来查、拿什么查」倒推键的选取。E2E 从服务端视角起测，恰好绕过了唯一会暴露它的一步。

## 解决方案

归档键改 `replayRoomKey() = boxCode || roomID`（gdRoom），文件名与 meta.roomId 同步；配套「一场一号」（整场结束平台销房、续场换新号），使**屏显号 ↔ 唯一一场 ↔ 唯一一档**三者恒等。用户亲手实打验证：屏显 317401 → 档名 `_317401_` → 输号即中。

## 预防规则

见 frontmatter。一句话：**检索键为查的人而设计；E2E 从用户拿到的凭据起测。**

## 续记（2026-08-04）：**08-02 的解法被证伪 —— boxCode 是可回收的进房码**

本条 08-02 的结论是「归档键改用屏显的 `boxCode`」。方向对（**归档键必须跟屏显同源**），
但**选错了那个号** —— `boxCode` 根本不是唯一标识。

### 现网实证

掼蛋游戏服自己的建房日志（`logs/othlog/`，`gameServer.ts:258` 打的
`create room code = X roomID = Y`）：

```
code = 205608  roomID = 125065
code = 205608  roomID = 125066
…                  …
code = 205608  roomID = 125085      ← 同一个 205608 被分配了 20 次
```

**`boxCode` 恒为 205608，`roomID` 却是 125065→125085 连号递增。**

旁证两条：
- 08-02 测滚子时同一档位**同时**开 3 个房，拿到 **3 个不同的** boxCode（205608 / 458761 / 287564）
  —— 所以它也不是「一档一个固定桌号」；
- `205608`、`458761` 这两个号 08-02 出现在**滚子**房上、08-04 又出现在**掼蛋**存档上。
  跨天跨玩法重现，是**后进先出的空闲号池**，不是巧合。

### 真正的语义

| 号 | 是什么 | 唯一吗 |
|---|---|---|
| `boxCode` | **进房码** —— 房号键盘输入用的那 6 位，好友房房主报给牌友的就是它。平台每建房分配一个，**用完回收再发** | ❌ 会重复 |
| `roomID` | 平台 DB **主键**，每建房一条，单调递增 | ✅ 永不重复 |

测试服上同时只有一桌活着，号被还回池子、下次又弹出来，于是**看着像"永远不变"**
（用户连打几场都是 205608，因此报了缺陷）；但它**有时也会变**（实测出现过 486501）——
**碰运气，不可依赖**，这比恒定更坏。

### 修正后的解法（2026-08-04 落地）

红线不变、选号改了：**屏上显什么，存档就按什么归档**，两边逐字同源。按房型分流：

| 房型 | 屏显 + 归档键 | 为什么 |
|---|---|---|
| 金币场 / 匹配场 | **`roomID`** | 撮合进场，房号本无"报给牌友"的用途，正好腾出来当整场唯一标识；且它就是服务端日志的 `[RoomID=…]` 前缀，**存档能一键对上日志** |
| 好友房 | **`boxCode`** 照旧 | 这个号房主要报给牌友进房，**动了牌友就进不来** —— 刻意不碰的那一半 |

落点两处，必须同改同上：`WMGDGameLayer_l.refreshRoomId()`（屏显）与
`gdRoom.replayRoomKey()`（归档）。

### 本条真正该留下的教训（比"选哪个号"更普适）

1. **"用户可见"是必要条件，不是充分条件。** 归档键要同时满足**可见**与**唯一**。
   08-02 只验了前者，就把一个 join code 抬举成了审计 ID。
2. **判断唯一性要看它的产品用途，不能看几次观测。** boxCode 的用途是"给人手输进房"——
   这种号天然被设计成可回收（否则号段会枯竭）。**从用途反推约束**比统计观测可靠。
3. **"看着不变"比"确实会变"更危险。** 测试环境负载低，回收池退化成常量，
   于是错误假设被环境掩护了整整两天。**低负载环境的稳定表象不能当作契约。**
4. **改了归档键，老档不会被回改。** 08-04 之前的档一律仍是 boxCode 口径、可能重号 ——
   查老档要靠时间与 `meta.players` 身份辅助分辨。这一条已写进
   `HANDOVER-复盘工具.md` 与测试指引，避免外部使用者按新口径去理解老档。
